# 基于开源 cad-mcp 的 WSL Arch Linux 与 Windows AutoCAD 跨环境 Agent 智能制图架构报告 (v1.0)

**项目名称**：面向 VLM 赋能教室光环境的多维教学黑板机构学设计与代际拓扑演进
**参赛赛道**：CASTIC 全国青少年科技创新大赛 · 工程学 / 计算机科学与机械交叉创新
**核心技术**：AI Agent (Antigravity) + 开源 cad-mcp 架构 + WSL 2 (Arch Linux) / Windows 11 跨系统协同 + AutoCAD 2026 COM 自动化参数化制图

## 一、 研发背景与工程痛点

在传统的机械创新设计与工程制图过程中，中学生通常面临以下三大研发痛点：
1. **手工绘图效率低下与代际迭代成本过高**：
   本项目从传统推拉黑板、第一代单轴翻转、第二代三维空间联动，到第三代多维叠合全覆盖（经历内侧铰链归位、双横梁套杆补齐、对角线双铰链重构），共经历了 16 轮设计演进。若采用传统手工鼠标在 CAD 界面拖拽绘图，每轮修改需耗费数小时，且极易因人为误操作产生尺寸链闭环误差或图元遗漏。
2. **跨系统环境天然割裂**：
   作者日常习惯在 **WSL 2 (Arch Linux)** 高性能终端环境下进行逻辑推导、数学建模、大模型 Agent 交互与 Git 版本控制；而工业级重型 CAD 设计软件 **AutoCAD 2026** 必须依托 Windows 宿主机的 DirectX/GPU 图形栈运行，两者在进程空间、文件路径和 API 接口上天然隔离。
3. **青少年科技创新“三自原则”自证诉求**：
   在 CASTIC 青创赛中，高中生拿出极高专业度的工业级图纸往往容易引发评审专家关于“是否大学导师/机构包办代做”的质疑。作者必须系统阐述如何利用现代 AI Agent 与开源工具链自主实现“以代码驱动几何、以数学约束参数”的智能化现代研发流程。

## 二、 开源 cad-mcp 核心思想与跨平台通信架构

为了攻克上述壁垒，本项目深度借鉴并扩展了开源社区 **cad-mcp (Computer-Aided Design Model Context Protocol)** 的核心设计理念，在 WSL Arch Linux 与 Windows 宿主机之间搭建了一套全自动化的 Agent 辅助工程制图流水线：

```
┌────────────────────────────────────────────────────────────────────────┐
│                   WSL 2 (Arch Linux) 控制与决策层                       │
│  • AI Agent (Antigravity) 机构学推理与尺寸链约束求解器                  │
│  • 对角线拓扑几何算法与运动学矩阵计算 (Python 3.12)                     │
│  • Git 版本控制与自动化审核日志生成                                      │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
                     JSON/RPC 协议与跨界调度桥梁
               (WSL interop / /mnt/d/ 共享文件系统总线)
                                   │
┌──────────────────────────────────▼─────────────────────────────────────┐
│                 Windows 宿主机 cad-mcp 适配执行层                       │
│  • cad-mcp 跨环境适配驱动器 (win32com.client COM Bridge)                │
│  • 工业级绘图动作调度：图层管理、图元生成、尺寸链约束、公差标注         │
│  • AutoCAD 2026 ActiveX API (AutoCAD.Application.24) 原生对象注入      │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
┌──────────────────────────────────▼─────────────────────────────────────┐
│                    AutoCAD 2026 物理图形引擎                           │
│  • 毫秒级生成 0 Hatch 纯机械工程矢量线框 (DWG)                          │
│  • 视图居中平铺 (ZoomAll) 与无损矢量保存                                │
│  • 高保真 4K (5800x4000) 工程图纸光栅化渲染输出 (PNG)                  │
└────────────────────────────────────────────────────────────────────────┘
```

### 1. 跨系统调度与文件系统无缝映射
- **统一存储基座**：统一将项目仓库挂载于宿主机高速 NVMe 固态硬盘（`D:\Desktop\pjhb\`），在 Arch Linux 终端通过 `/mnt/d/Desktop/pjhb/` 进行零延迟双向读写。
- **跨平台宿主执行**：在 Linux 端编写参数化绘图核心逻辑后，利用 WSL 互操作通道直接调度 Windows 宿主机环境下的专用 Python 解释器，避免了传统虚拟机与物理机之间的网络套接字开销。

### 2. COM 原生接口接管与工业图元注入
通过 Windows COM 机制，驱动器动态获取已打开或新启动的 AutoCAD 2026 单例实例：
```python
# 核心桥接实现逻辑
import win32com.client
acad = win32com.client.Dispatch('AutoCAD.Application')
doc = acad.ActiveDocument
ms = doc.ModelSpace

# 注入工程文字样式与 GB/T 标准字体
text_style = doc.TextStyles.Add('STYLE_GB_CN')
text_style.SetFont('SimHei', False, False, 134, 0)
doc.ActiveTextStyle = text_style

# 参数化绘制对角线铰链与双层黑板图元 (坐标由数学模型严格计算)
ms.AddLine(p1, p2)
```

### 3. 闭环质量自检与 4K 超清光栅化导出
- 绘图脚本完成图元添加后，自动执行 `doc.Regen(1)` 重新生成显示并调用 `acad.ZoomAll()`，使全图居中；
- 紧接着启动无损渲染模块，利用高分辨率光栅化算法将图纸几何坐标映射为 5800x4000 像素的 4K 纯工程机械黑白线框大图，直接回传至 Linux 端供 Agent 进行多视口防干涉视觉质检。
